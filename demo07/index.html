1. 技术需求与验收

接收可能由模型生成或外部传入的 JSON 工具请求，只有满足允许的工具名、参数类型、枚举和必填字段时才允许写入 SQLite。验收包括非法 JSON、缺参数、额外字段、不允许的优先级、不允许的工具名五类负例，以及合法工单创建和幂等重放。实验本身没有调用大模型。

2. 技术方案和数据链路

SCHEMA 采用 JSON Schema Draft 2020-12，最外层只允许 tool 与 arguments 两个字段，并将工具限制为 create_ticket。arguments 要求 request_key、title、priority，同时禁止额外字段。执行函数先调用 parse_and_validate()，再调用 TicketStore.create()；未校验通过的请求无法进入有副作用的路径。

3. 核心实现及关键代码

3.1 字段边界与工具白名单

对应源码：structured_gate.py — 关键代码节选（省略上下文，不可直接独立执行）

SCHEMA = {
  "type":"object", "additionalProperties":False,
  "required":["tool","arguments"],
  "properties":{
    "tool":{"const":"create_ticket"},
    "arguments":{ "type":"object", "additionalProperties":False,
      "required":["request_key","title","priority"],
      "properties":{ "priority":{"enum":["low","normal","high"]}}}}}

外层和内层都设置 additionalProperties=False，防止外加 admin、approved 等非预期字段。const 禁止将工具名偷偷换成其他操作。实际 Schema 还约束了 request_key 格式和 title 长度；展示的是源码节选，不能把节选独立当作完整校验器。

3.2 解析失败与执行分离

对应源码：structured_gate.py — 关键代码节选（省略上下文，不可直接独立执行）

request = json.loads(raw)
issues = sorted(VALIDATOR.iter_errors(request), key=lambda e:(list(map(str,e.absolute_path)),e.message))
if issues:
    return {"ok":False,"category":"schema_rejected","errors":[...]}
# execute():
result = parse_and_validate(raw)
if not result["ok"]: return result
ticket = ticket_store.create(args["request_key"], args["title"])

先分离语法错误 malformed_json 与字段错误 schema_rejected；absolute_path 有助于定位字段级错误。只有 ok=True 才调用 SQLite。priority 此处虽然合法必填，但 TicketStore 并没有保存优先级，这是集成时需要补齐的数据契约缺口。
