01｜这项技术要解决什么问题

上游 Agent 或程序生成的 JSON 可能缺少字段、携带错误枚举或试图调用不允许的工具。直接用这些字符串写入数据库会使错误从格式层传播到业务状态。

02｜核心技术与实现机制

使用真正的 JSON Schema Draft 2020-12 校验 JSON 结构、必填字段、枚举和额外属性，然后决定是否允许调用共享 SQLite 工单存储。输入由合成的上游生产者构造，**这里没有运行 LLM**。

03｜实际实验输入与执行过程

五种非法请求分别包含畸形 JSON、缺少 request_key、未许可 admin 字段、错误 priority 枚举和非允许的 delete_records 工具。五项必须全部拒绝且工单数为零；有效创建并重试后仍只有一条记录。

真实校验和 SQLite 数据副作用检查通过，输出 JSON_SCHEMA_TOOL_GATE_E2E_PASS，记录五种拒绝原因与幂等重复执行结果。
