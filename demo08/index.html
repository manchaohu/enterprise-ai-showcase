推理服务延迟：超时与降级为什么重要？

把 AI 接入同步业务接口，延迟有时比生成内容本身更决定用户体验。接口超时以后，需要明确什么时候回退、改走异步或返回待处理状态，避免上游一直等待。

01｜这项技术要解决什么问题

把 AI 接入同步业务接口，延迟有时比生成内容本身更决定用户体验。接口超时以后，需要明确什么时候回退、改走异步或返回待处理状态，避免上游一直等待。

02｜核心技术与实现机制

项目启动真正的 localhost 多线程 HTTP 服务，但它返回的是 deterministic-mock 模拟推理响应。客户端用线程池并发发请求，测量真实 HTTP 往返时间，并在服务故意延时的情况下触发超时与兜底。

03｜实际实验输入与执行过程

四个工作线程完成十二次设定 25ms 处理延时的 HTTP 请求，记录每次耗时并算出 P50/P95；另发一次服务器端设定 400ms 延时、客户端超时 80ms 的请求，检查返回 queued-for-later。

04｜真实验收与观察到的结果

项目真实运行了 HTTP 通信与超时机制，记录 completed_requests=12、concurrency=4、p50_ms、p95_ms、timeout_fallback，以及 real_llm=false。它验证集成控制链路，而非任何特定模型性能。

06｜能力边界与后续深化

没有模型权重、GPU 或真实 LLM。12 个请求和模拟服务的 25ms 处理延时，不能证明生产 P95、跨地域网络时延或线上 SLO。
