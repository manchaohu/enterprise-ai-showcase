01｜技术为什么有用

从扫描表单提取结构化信息不只是 OCR 识字，还要结合词的位置、页面图像和上下文判断哪些词是标题、问题或答案。模型成功执行并不保证字段能被正确抽取，因此需要展示真实错误率。

02｜核心技术与处理流程

运行 FUNSD 微调版 LayoutLMv3，输入两张真实公开测试表单图、数据集已有 OCR 词和归一化边界框，禁用内部 OCR。模型在 CPU 上预测词级 BIO 角色，再根据参考标注计算匹配情况，保留 logits 与原图哈希。

03｜真实执行的实验过程

样本 01 有 223 个词，样本 02 有 167 个词，共 390 个词。模型将其中 174 个预测为非 O；对应参考标注匹配分别为 83/223（37.22%）与 112/167（67.07%）。

04｜已观测结果与验收证据

真实预训练/微调模型前向推理与独立证据核对成功，但综合词级标签仅 195/390（50.0%）一致。这是一个很有价值的负面质量事实：演示通过不等于业务可用。

05｜复现程序与运行证据

按照工程仓库环境要求执行以下命令；公开网站并不直接运行模型。

cd projects/18-document-layout
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python layout_e2e.py
python verify_evidence.py

私有仓库源码与 Actions 可能需要授权才能访问；本站不再分发模型权重和私人材料。

06｜能力边界与后续深化

既有 OCR 词和框由数据集提供，本实验没有从图片重新识字。词级角色不能自动完成问答字段配对、键值提取或可靠表单解析；50.0% 不是完整 FUNSD 基准分数。
