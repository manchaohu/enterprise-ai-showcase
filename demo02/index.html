1. 技术需求与验收条件

处理包含电子文本、扫描图像和规则表格的 PDF 文件，输出统一的页级文字、发票字段和表格行。测试输入由 ReportLab 与 Pillow 在运行时生成，包含电子发票 INV-001、扫描发票 SCAN-002 和商品明细表；金额均为 145.80。验收要求 PDF 文本直接解析、扫描页面进入 Tesseract OCR 分支、表格读取到 Widget 与 Service 两条数据。

2. 技术方案与执行链

fitz（PyMuPDF）负责读取 PDF 页面及扫描页渲染；pytesseract 将图像传给 Tesseract OCR；pdfplumber 针对可识别网格提取表格。最后，规则表达式从合并文字中解析票号、日期、总额。这个实现将页面抽取、结构化字段和表格提取保持为独立环节，适合排查某个阶段的错误。

3. 核心实现与代码要点

3.1 文本检测与 OCR 分支

源码位置：document_extract.py · 关键片段（其余逻辑见完整源码）

text = page.get_text("text").strip()
method = "pdf_text"
if not text:
    pix = page.get_pixmap(matrix=fitz.Matrix(2, 2), alpha=False)
    img = Image.frombytes("RGB", (pix.width, pix.height), pix.samples)
    text = pytesseract.image_to_string(img, config="--psm 6").strip()
    method = "ocr_tesseract"

只有页面可提取文字为空时才切换到 OCR。Matrix(2,2) 提高渲染像素密度，--psm 6 表示采用单个统一文本块布局假设，适合这里的简单票据。对于既含电子文本又含扫描区域的混合页面，这种整页开关可能漏掉图像区域，工程化时应改为块级/区域级判断。method 随页面输出，可以判断实际走了哪条路径。

3.2 表格识别与字段解析

源码位置：document_extract.py · 关键片段（其余逻辑见完整源码）

for grid in page.extract_tables():
    tables.append({"page": index + 1, "rows": grid})
patterns = {
    "invoice_id": r"Invoice\s*ID\s*:\s*([A-Z0-9-]+)",
    "date": r"Date\s*:\s*(\d{4}-\d{2}-\d{2})",
    "total": r"Total\s*:\s*([0-9]+(?:\.[0-9]{2})?)",
}

表格输出保留页码和原始二维行，不将 Item、Qty、Amount 自动解释为金额关系。正则专门针对英语票据标签与固定日期格式，字段找不到时返回 None。原始程序在不同文档类型上使用同一模式集，因此复杂模板、跨行字段、手写字和国际化票据需要额外解析层。
