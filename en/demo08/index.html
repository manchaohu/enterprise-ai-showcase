01｜The practical question

Response latency can determine whether a model-dependent service fits a synchronous business path. HTTP clients need deliberate timeouts and fallback behavior rather than waiting indefinitely for simulated or real inference.

02｜How the system works

A genuine threaded localhost HTTP server exposes an inference-like endpoint, but its payload is explicitly deterministic-mock—not a pretrained model. Client threads measure request elapsed time and exercise timeout-driven fallback.

03｜Experiment inputs and execution

Twelve HTTP calls with an intended 25 ms service delay are issued through four worker threads. P50/P95 are computed from actual local response times; another request has 400 ms service delay but an 80 ms client timeout, forcing queued-for-later.

04｜What acceptance actually observed

The observed output records 12 completed requests, concurrency 4, p50_ms, p95_ms and a timeout fallback of queued-for-later, explicitly tagging real_llm=false. These are integration mechanics, not model latency measurements.

06｜Limits and future deepening

No pretrained model, actual LLM inference or production load. Twelve local calls around a synthetic service delay cannot certify model P95, inter-region networking or operational SLOs.
