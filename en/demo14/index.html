01｜The practical question

A real agent-like tool flow lets the model propose the function name and arguments, while the trusted application validates and authorizes any resulting side effect. Prewritten calls cannot prove model-side tool selection.

02｜How the system works

Pretrained Qwen2.5-0.5B-Instruct receives actual tools definitions in the tokenizer chat template and generates tool_call JSON on CPU. The application then validates schema, applies a Boolean approval decision and calls the SQLite TicketStore.

03｜Experiment inputs and execution

Three English requests test model-proposed create, get and close operations. For mutating calls, the exact proposal is rejected without approval and succeeds with an application-supplied approval; crafted negative payloads are not attributed to model behavior.

04｜What acceptance actually observed

The successful Actions run preserves genuine generated tool proposals, validation, denied side effects, approved SQLite updates and direct readback. No canned function-call proposal replaces the model output.

06｜Limits and future deepening

Approval is a trusted application Boolean rather than authenticated human authorization. No MCP transport, hosted provider native tool-call API, multilingual reliability or production security evaluation was performed.
