TinyTimeMixer | Forecast 96 future hours from 512 past hours

IBM Granite TinyTimeMixer R2 on actual ETTh1 transformer oil-temperature measurements, with independent evidence and honest comparisons to simple forecasts.

← Back to tutorial catalog

01 | Forecast requirement and metrics

Operational systems produce streams of equipment temperature, throughput and capacity measurements. Teams may want to predict likely future changes, not just react to a current number. But a neural predictor must justify its complexity: repeating the last observed value, or repeating a recent daily pattern, might sometimes work just as well.

The central question is whether a pretrained model adds predictive value over such simple baselines. This experiment compares actual forecasts with the later observed values rather than judging a model by a visually appealing curve. It is an engineering demonstration, not a certified power-system monitoring product.

02 | Model contract: 512 input hours, 96 output hours

This demo loads pretrained IBM Granite TinyTimeMixer R2 weights and processes 512 consecutive hourly oil-temperature observations from the public ETTh1 dataset. The model predicts the following 96 hours without any new training or fine-tuning. The checkpoint is fixed at immutable commit d6a79570cac0f33d526601cd3a0fc7c80a8f9a2f.

Time leakage matters: the program calculates normalization parameters exclusively from observations available before the forecast period. It uses the future 96 true readings only after inference to measure error. Correct script-level separation does not prove that upstream pretraining never included related ETT data.

03 | Baselines and evaluation pipeline

Alongside TTM, the code produces two explicit alternatives. A last-value persistence forecast holds the final historical reading constant for 96 hours. A 24-hour seasonal-naive forecast repeats the last full day four times. Each is compared with the actual future values using MAE (mean absolute error) and RMSE (root mean squared error).

The saved evidence includes 512 history points per case, all 96 future observations, every model prediction, both baselines, timestamps, and checksums. An independent verifier recomputes the baseline predictions and descriptive errors rather than relying solely on a printed PASS marker.

04 | Results from two forecast windows

Executed source excerpts; full code is in the private repository: projects/21-real-timeseries/ttm_e2e.py

Leakage-free history and scaling

`split_at` selects 512 historical readings before the forecast origin and holds out 96 subsequent readings for evaluation. The scaler is fitted on history only to avoid future leakage, with explicit checks for window length and degenerate scale.

def split_at(rows,end_index:int):
    if end_index<CONTEXT or end_index+HORIZON>len(rows):
        raise ValueError("Need 512 historical points plus 96 forward ground-truth points")
    past=rows[end_index-CONTEXT:end_index]
    future=rows[end_index:end_index+HORIZON]
    if len(past)!=CONTEXT or len(future)!=HORIZON:
        raise ValueError("Window length mismatch")
    # Fit only on the 512 historical observations; no future leakage.
    values=[v for _,v in past]
    mean=statistics.mean(values)
    std=statistics.pstdev(values)
    if not 0.000001<std<1000000:
        raise ValueError("Degenerate history-only standard scaler")
    return past,future,mean,std

Tensor shapes and matched baselines

The normalized tensor has shape `[1,512,1]`; the expected TinyTimeMixer output is `[1,96,1]`. Inverse scaling uses the historical mean and standard deviation. MAE/RMSE are compared with last-value and 24-hour seasonal baselines on matching future periods.

    for number,end in enumerate((len(rows)-2*HORIZON,len(rows)-HORIZON),start=1):
        past,future,mean,std=split_at(rows,end)
        normalized=[(value-mean)/std for _,value in past]
        tensor=torch.tensor(normalized,dtype=torch.float32).view(1,CONTEXT,1)
        run_start=time.monotonic()
        with torch.inference_mode():
            output=model(past_values=tensor,return_loss=False)
        pred=output.prediction_outputs
        if list(pred.shape)!=[1,HORIZON,1]:
            raise RuntimeError(f"Unexpected trained model forecast shape {list(pred.shape)}")
        floats=[float(x)*std+mean for x in pred[0,:,0].detach().cpu().tolist()]
        if not all(math.isfinite(v) for v in floats):
            raise RuntimeError("Model forecast contains nonfinite values")
        actual=[value for _,value in future]
        persistence,seasonal=naive_forecasts([v for _,v in past])

Integration boundaries

Two ETTh1 windows are not a general benchmark. Enterprise use requires missing data, drift, versioning, and domain-specific rolling tests.

06 | Reproduction and evidence

Seeing actual pretrained computation and auditable numeric errors is useful; two local evaluation windows are still not a broad test. This experiment does not establish production accuracy on a company's equipment, reliability under missing samples, shifts in temperature distribution, decision benefits from alerts, or a guaranteed latency service level. The upstream training corpus may include related ETT material.

Scope boundary: neither a probabilistic uncertainty interval nor training-data-disjoint validation was established. License and redistribution conditions for the model and the source dataset must be considered independently.
