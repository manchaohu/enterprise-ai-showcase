1. Requirements and acceptance

Synthesize two English sentences with a pretrained Piper ONNX voice into mono 16 kHz WAV. Verify model hash, real neural synthesis, frames, duration, amplitude and output fingerprints. A nonempty waveform does not establish intelligibility or text accuracy.

2. Architecture and execution path

The en_US-lessac-low voice comes from rhasspy/piper-voices release v1.0.0. The script validates the ONNX weight checksum, loads the Piper voice on CPU, writes PCM WAV and records text, duration, RMS, peak amplitude and SHA-256. Library and voice licensing are separate checks.

3. Core implementation

3.1 Verify downloaded voice assets

Source：tts_e2e.py · Selected excerpt; full logic in repository

download_file(VOICE_ROOT + VOICE_FILE, weight_path, VOICE_SHA256)
download_file(VOICE_ROOT + VOICE_CONFIG_FILE, config_path)
if model_config["audio"]["sample_rate"] != 16000:
    raise AssertionError("Unexpected voice configuration")
if sha256(weight_path) != VOICE_SHA256:
    raise AssertionError("Pretrained model integrity failed")

Downloads are staged in .part and promoted only after checks pass. The voice weight has a fixed SHA-256 and configuration must request 16 kHz. Unlike the ONNX weight, the config's hash is recorded but not compared to a pre-pinned expected hash.

3.2 Run neural speech synthesis

Source：tts_e2e.py · Selected excerpt; full logic in repository

voice = PiperVoice.load(str(weight_path), config_path=str(config_path))
with wave.open(str(dest), "wb") as writer:
    voice.synthesize_wav(case["text"], writer)
metrics = inspect_wav(dest)

PiperVoice.load() loads the pretrained ONNX voice; synthesize_wav() writes generated PCM frames into the WAV writer. eSpeak-generated audio is not substituted. A service should keep the voice loaded and enforce input-length limits.

3.3 Validate PCM and WAV properties

Source：tts_e2e.py · Selected excerpt; full logic in repository

if channels != 1 or sample_width != 2 or rate < 8000:
    raise AssertionError("Expected mono 16-bit PCM")
rms = math.sqrt(sum(v * v for v in values) / len(values))
peak = max(abs(v) for v in values)
if not (0.5 <= duration <= 45 and rms >= 40 and peak >= 200):
    raise AssertionError("Invalid/near silent output")

The checks reject silence-like or malformed outputs. RMS measures average signal energy and peak detects extremes, not correctness or naturalness. The routine assumes signed 16-bit PCM; float or multichannel audio requires adjusted decoding and thresholds.

5. Integration and operational design

Reproduction commands (requires private repo access)

cd projects/16-real-tts
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python tts_e2e.py
python verify_evidence.py

A TTS service can retain a loaded Piper voice, queue text requests and return WAV or transcoded audio. Production operation needs streaming, text segmentation, caching, pronunciation control, listening evaluations and a licensing review.

6. Limits and evidence

Two English sentences only. Acoustic checks do not prove spoken text or perceptual quality. Piper code and voice/data licensing must be reviewed separately before public redistribution. Concurrency and service SLOs were not measured.
