Demo 05｜SQLite async queue: leases, retries and dead-letter states

1. Requirements and acceptance

Persist idempotent jobs, claim them with leases, reschedule failures, reclaim work after simulated crashes, and move exhausted retries to a dead-letter state. SQLite is the storage backend and test time comes from a simulated logical clock. The experiment validates transitions, not message-broker throughput.

2. Technical design and data flow

Jobs track state, attempts, ready_at, lease_until and unique request_key. Submit and claim use BEGIN IMMEDIATE to coordinate competing SQLite writers. Failed work is deferred by exponential backoff. An expired running lease permits a new claim.

3. Core code and implementation details

3.1 Idempotent submission

Source：queue_store.py — Selected excerpt, surrounding context omitted; not standalone executable

db.execute("BEGIN IMMEDIATE")
db.execute("INSERT OR IGNORE INTO jobs(request_key,payload) VALUES (?,?)",(key,payload))
job = db.execute("SELECT * FROM jobs WHERE request_key=?", (key,)).fetchone()
if job["payload"] != payload:
    db.rollback()
    raise ValueError("idempotency key conflict")

request_key is UNIQUE. Duplicate keys with identical payloads return the original job; a key reused for different work is rejected. This prevents duplicate enqueueing but does not guarantee exactly-once side effects in downstream systems.

3.2 Claim lease and retry backoff

Source：queue_store.py — Selected excerpt, surrounding context omitted; not standalone executable

row = db.execute("""SELECT * FROM jobs WHERE
 (state='queued' AND ready_at<=?) OR
 (state='running' AND lease_until<=?)
 ORDER BY id LIMIT 1""", (now,now)).fetchone()
# claim updates attempts and lease_until in the same write transaction
ready = now + (2 ** row["attempts"]) if not dead else now

Claims include ready queued jobs and running jobs with expired leases. Each claim increments attempts; the first failure delays by 2^1 logical seconds, then backoff grows. Exhaustion moves work to dead. Production workers need lease renewal, clock discipline and stronger concurrency tests.

4. Observed results and evidence

Evidence ASYNC_SQLITE_QUEUE_E2E_PASS confirms duplicate submission is idempotent, conflicting keys fail, delayed retry and lease reclaim work, and the third attempt reaches dead. A separate job ends done. No multi-node load or live crash-recovery benchmark was performed.

5. Integration and operational use

Use as a prototype for small ingestion, notification or sync jobs: API submits and returns a job ID, worker claims, UI polls. Add idempotency tokens for external effects, dead-letter observability, alerting, timeouts and retention; replace with a dedicated broker as scale grows.
