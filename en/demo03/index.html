1. Requirements and acceptance

Trace HTTP requests across independent gateway and backend processes, including downstream client calls and storage operations. Acceptance includes normal, slow and error requests; a collector receives real OTLP spans and Jaeger retrieves them by trace ID.

2. Architecture and execution path

Compose runs gateway, backend, OpenTelemetry Collector and Jaeger. Each application exports spans as OTLP/HTTP protobuf to Collector /v1/traces; Collector forwards them to Jaeger. Shared trace IDs correlate the request, while span and parent identifiers express its hierarchy.

3. Core implementation

3.1 Initialize OTLP tracing

Source：src/otel_demo/otlp_service.py · Selected excerpt; full logic in repository

provider = TracerProvider(resource=Resource.create({
    "service.name": name, "service.version": "2.0-demo"}))
exporter = OTLPSpanExporter(endpoint=endpoint, timeout=5)
provider.add_span_processor(BatchSpanProcessor(exporter,
    schedule_delay_millis=500))
tracer = provider.get_tracer("otel_demo.otlp_service")

Resource service.name separates gateway and backend telemetry. BatchSpanProcessor buffers exports; the 500 ms delay is scheduling configuration, not an end-to-end latency target. Explicit flush and shutdown reduce the chance of losing final spans.

3.2 Collector receive/forward pipeline

Source：collector-config.yaml · Selected excerpt; full logic in repository

receivers:
  otlp:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
processors:
  batch:
    timeout: 1s
exporters:
  otlp_http/jaeger:
    endpoint: http://jaeger:4318

Both applications post to http://collector:4318/v1/traces. Collector receives and forwards to Jaeger. Port 4318 is the OTLP receiver/exporter path, while 16686 serves Jaeger UI. Configuration text alone is not proof of successful transport.

3.3 Verify retrieved trace structure

Source：scripts/verify_collector_jaeger.py · Selected excerpt; full logic in repository

REQUIRED = {"gateway.http.request", "gateway.http.client.backend",
            "backend.http.request", "backend.storage.query"}
MODES = ("ok", "ok", "ok", "slow", "slow", "error")
# Verifier polls Jaeger /api/traces/{trace_id} and checks required spans.

The verifier sends six calls. Five should yield HTTP 200 and the error mode HTTP 502. Each trace must include four required spans and both service names. Missing Jaeger retrieval fails the test. /api/traces/{id} is an internal UI API, unsuitable as a stable production contract.

5. Integration and operational design

Reproduction commands (requires private repo access)

cd projects/03-opentelemetry
python -m pip install -r requirements.txt
python scripts/run_compose_e2e.py

Instrument inbound HTTP handlers, outbound client calls and storage operations, propagating trace context across service boundaries. Production setups need sampling, sensitive-attribute scrubbing, retention and telemetry overhead budgets. The existing GitHub Actions Docker path can replace local Docker when unavailable.

6. Limits and evidence

The historical Jaeger result does not establish production telemetry reliability. High-volume sampling, async causality, sensitive-data controls and retention remain untested. Raw trace artifact availability is currently a documented evidence gap.
