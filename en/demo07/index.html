JSON Schema gates: rejecting unsafe tool arguments

Tool payloads can be malformed, omit required fields or request unauthorized actions. The boundary between a generated JSON string and a side-effecting business operation needs explicit validation.

01 · The problem this technology solves

Tool payloads can be malformed, omit required fields or request unauthorized actions. The boundary between a generated JSON string and a side-effecting business operation needs explicit validation.

02 · Core mechanism

Draft 2020-12 JSON Schema validates object structure, required properties, enum values and extra fields before executing the SQLite-backed create_ticket operation. Inputs are crafted fixtures, not outputs of a running LLM.

01Parse JSON payload
02Check Draft 2020-12
03Reject malformed requests
04Execute valid SQLite call

The flow diagram summarizes the implemented steps; it is not a measured model-output visualization.

03 · What the experiment actually ran

Five negative inputs cover invalid JSON syntax, missing request_key, an unexpected admin field, wrong priority enum and unauthorized delete_records tool. All must be rejected with zero inserts; one valid creation and its idempotent replay leave exactly one ticket.

04 · Observed acceptance evidence

Actual schema checks and SQLite state assertions passed; evidence reports JSON_SCHEMA_TOOL_GATE_E2E_PASS, five rejection categories and the idempotent valid replay.

06 · Limits and the next deeper question

This does not test constrained LLM decoding, model generation quality, prompt-injection defenses or production authorization. The success belongs to the application validator, not the model.
