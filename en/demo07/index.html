1. Requirements and acceptance

Accept an untrusted JSON tool request and block business effects unless the tool name and every required argument satisfy JSON Schema. Five crafted invalid cases must be rejected without a SQLite write. Valid creation and identical replay must succeed. No model inference is performed in this demo.

2. Technical design and data flow

An explicit Draft 2020-12 schema restricts the envelope to tool and arguments, fixes the only permitted tool to create_ticket, and requires request_key, title and priority without extra fields. execute() invokes validation before TicketStore.create(), providing a clear side-effect boundary.

3. Core code and implementation details

3.1 Tool and field allow-list

Source：structured_gate.py — Selected excerpt, surrounding context omitted; not standalone executable

SCHEMA = {
  "type":"object", "additionalProperties":False,
  "required":["tool","arguments"],
  "properties":{
    "tool":{"const":"create_ticket"},
    "arguments":{ "type":"object", "additionalProperties":False,
      "required":["request_key","title","priority"],
      "properties":{ "priority":{"enum":["low","normal","high"]}}}}}

Both levels reject undeclared fields. A constant tool name prevents dispatch to disallowed operations. The full schema also constrains request_key pattern and title length; this excerpt is not the complete standalone schema.

3.2 Parse failure and side-effect boundary

Source：structured_gate.py — Selected excerpt, surrounding context omitted; not standalone executable

request = json.loads(raw)
issues = sorted(VALIDATOR.iter_errors(request), key=lambda e:(list(map(str,e.absolute_path)),e.message))
if issues:
    return {"ok":False,"category":"schema_rejected","errors":[...]}
# execute():
result = parse_and_validate(raw)
if not result["ok"]: return result
ticket = ticket_store.create(args["request_key"], args["title"])

Parsing distinguishes malformed JSON from schema violations and preserves field paths. Execution only proceeds for ok=True. Priority is validated as mandatory but not persisted by the underlying TicketStore—a concrete integration gap requiring an explicit data-contract decision.

5. Integration and operational use

Place validation between an agent tool router and the business API. Schema conformance is not authorization. Add identity, resource permissions, idempotency and workflow preconditions; version schemas and regression-test invalid inputs.
