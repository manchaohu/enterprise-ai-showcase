01 · The problem this technology solves

Digital PDFs, scanned pages and ruled tables require different extraction methods. This experiment demonstrates choosing a text parser, an OCR engine or a table extractor and returning structured fields instead of assuming all PDFs contain selectable text.

02 · Core mechanism

PyMuPDF extracts embedded text and renders scanned pages; Tesseract/pytesseract performs OCR; pdfplumber extracts table rows. ReportLab and Pillow construct synthetic invoice fixtures at runtime, so no private invoices are needed.

03 · What the experiment actually ran

Three synthetic PDFs are produced: a text invoice with ID INV-001, a rasterized scanned invoice SCAN-002, and a ruled table with Widget and Service rows. Acceptance checks IDs, date 2026-10-19, total 145.80, actual ocr_tesseract usage and recovered table rows.

04 · Observed acceptance evidence

The dedicated Actions run passed real PDF text parsing, scanned OCR and table extraction, writing PDF_OCR_TABLE_E2E_PASS evidence. It proves this synthetic three-file flow ran, not reliable extraction across arbitrary invoices.

05 · Reproduce the experiment

From the repository root, use the experiment's documented runner. This snippet is a reference command, not a live in-browser executable.

sudo apt-get install tesseract-ocr
cd projects/02-document-extraction
python -m pip install -r requirements.txt
python verify_document_e2e.py

Model downloads, external tools, OS-specific requirements and permissions are described in the private project.

06 · Limits and the next deeper question

English synthetic forms, clean OCR and simple ruled tables only. Chinese OCR, handwritten invoices, scanned table recovery, adversarial PDFs, complex layouts and real-world field accuracy remain unassessed. Historic archive gaps are separate from this reimplemented demo.
