1. Requirements and acceptance

Process PDFs containing selectable text, scanned images and ruled tables; return page text, invoice fields and table rows. Runtime-generated fixtures cover INV-001, SCAN-002, and a two-line item table. The expected total is 145.80. Acceptance checks direct PDF extraction, actual Tesseract fallback for a scanned page, and extraction of both table entries.

2. Architecture and execution path

PyMuPDF reads digital text and rasterizes scanned pages; pytesseract invokes Tesseract on rendered images; pdfplumber extracts grid-based tables. Regular expressions map accumulated text into invoice ID, date and total. Separate page, field and table results make failures traceable to individual stages.

3. Core implementation

3.1 Digital-text and OCR branches

Source：document_extract.py · Selected excerpt; full logic in repository

text = page.get_text("text").strip()
method = "pdf_text"
if not text:
    pix = page.get_pixmap(matrix=fitz.Matrix(2, 2), alpha=False)
    img = Image.frombytes("RGB", (pix.width, pix.height), pix.samples)
    text = pytesseract.image_to_string(img, config="--psm 6").strip()
    method = "ocr_tesseract"

OCR runs only when a page returns no selectable text. Matrix(2,2) doubles rasterization scale and --psm 6 assumes a uniform text block. Mixed digital/scanned pages can bypass OCR even when some image regions require it; use regional selection in a production extractor. The persisted method field exposes the path taken.

3.2 Table and field extraction

Source：document_extract.py · Selected excerpt; full logic in repository

for grid in page.extract_tables():
    tables.append({"page": index + 1, "rows": grid})
patterns = {
    "invoice_id": r"Invoice\s*ID\s*:\s*([A-Z0-9-]+)",
    "date": r"Date\s*:\s*(\d{4}-\d{2}-\d{2})",
    "total": r"Total\s*:\s*([0-9]+(?:\.[0-9]{2})?)",
}

The table output preserves page numbers and raw rows. It does not infer invoice arithmetic. Regex matching targets English labels and a fixed date format; missing fields become None. Complex layouts, handwriting, cross-line fields and multilingual templates require a separate field extraction layer.

5. Integration and operational design

Reproduction commands (requires private repo access)

sudo apt-get install -y tesseract-ocr
cd projects/02-document-extraction
python -m pip install -r requirements.txt
python verify_document_e2e.py

A business pipeline can first classify document pages, then route regions to text extraction, OCR and table parsers. Preserve page coordinates, source spans, confidence and correction history before generating business JSON. The demo does not provide such coordinates or scores. Untrusted PDFs additionally require isolation, size limits, PII handling and review.

6. Limits and evidence

Only three constructed English files were exercised. Chinese, real invoices, handwriting, skew, rotated pages, mixed digital-image regions and malicious PDFs remain untested. The program checks extracted rows rather than independently reconciling invoice totals.
