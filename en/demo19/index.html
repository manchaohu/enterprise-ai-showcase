1. Requirements and acceptance

Given five candidate passages, use a real MS MARCO Cross-Encoder to score each query–passage pair and reorder results. Constructed queries target Jaeger trace inspection and OCR on scanned PDFs. Distinct expected top results demonstrate model-based reranking on this fixture, not enterprise retrieval quality.

2. Technical design and data flow

The pinned MS MARCO MiniLM cross-encoder produces one classification logit per joint query/passage input. Each query is repeated across five candidates. The [5,1] scores are sorted descending with input-order tie breaks. Raw logits are ranking signals, not calibrated relevance probabilities.

3. Core code and implementation details

3.1 Joint pair tokenization

Source：reranker_e2e.py — Selected excerpt, surrounding context omitted; not standalone executable

batch = tokenizer([case["query"]]*len(DOCUMENTS),
  [doc["text"] for doc in DOCUMENTS],
  padding=True,truncation=True,max_length=256,return_tensors="pt")
with torch.inference_mode():
    logits = model(**batch).logits
if list(logits.shape) != [len(DOCUMENTS),1]:
    raise RuntimeError("Unexpected trained ranking head")

A Cross-Encoder jointly encodes query and passage. Each candidate needs one paired forward computation, typically batched; long passages are truncated at 256 tokens. This differs from separately indexed bi-encoder sentence embeddings.

3.2 Rank raw model scores

Source：reranker_e2e.py — Selected excerpt, surrounding context omitted; not standalone executable

scores=[float(x) for x in logits.detach().cpu().view(-1).tolist()]
order = sorted(range(len(DOCUMENTS)),
               key=lambda i:(-float(scores[i]),i))
ranked=[{"rank":rank, "id":DOCUMENTS[i]["id"],
         "model_raw_logit":round(scores[i],7)}
         for rank,i in enumerate(order,start=1)]

Sorting uses model logits only, with input-index tie-breaking; expected IDs do not feed back into ranking. Logits may be negative and should not be compared as calibrated probabilities across unrelated queries. Reference IDs are checked only afterward.

5. Integration and operational use

Place after lexical/dense recall on a bounded candidate set. Limit token length and batch size, manage inference latency, and evaluate relevance using labels and nDCG. Cross-Encoder reranking cannot recover documents excluded by the initial retriever.

6. Limits of validation

Five constructed English passages and two queries, no first-stage retrieval module, significance analysis or load benchmark.
