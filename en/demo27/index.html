SQLite + BFS | Directed multi-hop paths with source quotations

A runnable SQLite directed graph with breadth-first multi-hop traversal, quotes linked to original snippets, and independent exhaustive verification.

← Back to tutorial catalog

01 | One answer can span several documents

Imagine diagnosing a company's service dependency. One document says that a service depends on an indexer, a second says the indexer runs on a database, and a third identifies the database's maintenance team. None of these documents alone gives the complete answer to “Which team maintains the database used by this service?”

Graph-based evidence traversal connects explicit facts across documents. Entities become nodes, facts such as “depends on” or “maintained by” become directed edges, and a multi-hop path makes the relationship traceable.

02 | Directed edges are stored with their source quotations

The real Demo 27 program reads five synthetic English documents and five manually curated relationships from data/evidence.json. Each edge contains a source entity, predicate, target entity, source document ID and exact supporting quote. The loader checks that the quote actually occurs in the referenced document.

The graph is then stored in an in-memory SQLite table. Python breadth-first search (BFS) finds shortest directed evidence paths within a requested maximum number of hops. The main program queries outgoing edges and follows valid transitions, retaining the evidence accumulated along each path and avoiding repeated visits. Reaching the specified hop limit prevents it from expanding further. Direction matters: a path from Atlas to Foxtrot does not imply the reverse path exists.

The independent verification script is deliberately a different algorithm. It exhaustively enumerates allowed edge sequences and checks the returned paths, shortest lengths, edge identities and supporting quotes against the original synthetic documents.

Validate evidence before constructing edges

`load` checks that each relation refers to an existing document and that its quotation is contained in that document. `graph_db` stores source node, predicate, destination node, document ID, and quotation in SQLite. The inputs are curated fixture relations, not AI entity extraction.

def load():
    d=json.loads(DATA.read_text(encoding="utf8"))
    docs={x["id"]:x["text"] for x in d["documents"]}
    assert len(docs)==len(d["documents"])
    for r in d["relations"]:
        assert r["document_id"] in docs and r["quote"] in docs[r["document_id"]]
        assert all(r[k] for k in ("source","target","predicate"))
    return d

def graph_db(d):
    db=sqlite3.connect(":memory:")
    db.execute("CREATE TABLE edges (src TEXT, predicate TEXT, dst TEXT, document_id TEXT, quote TEXT)")
    db.executemany("INSERT INTO edges VALUES (?,?,?,?,?)",[(r["source"],r["predicate"],r["target"],r["document_id"],r["quote"]) for r in d["relations"]])
    return db

BFS returns a directed shortest-hop evidence path

The BFS queue holds current node, path, and a path-specific visited set. Directed edges are traversed in breadth-first order until the target is reached or `max_hops` is exhausted; successful output retains the supporting quotation for each edge. `None` means no path, and empty output means matching endpoints.

def shortest_path(db, start, end, max_hops):
    if start==end: return []
    queue=deque([(start,[],{start})])
    while queue:
        node,path,visited=queue.popleft()
        if len(path)>=max_hops: continue
        rows=db.execute("SELECT src,predicate,dst,document_id,quote FROM edges WHERE src=? ORDER BY predicate,dst,document_id",(node,)).fetchall()
        for a,p,b,d,q in rows:
            edge={"source":a,"predicate":p,"target":b,"document_id":d,"quote":q}
            nextpath=path+[edge]
            if b==end:return nextpath
            if b not in visited:queue.append((b,nextpath,visited|{b}))
    return None

Integration boundaries

Enterprise use needs provenance auditing, ACL-aware edges, relation updates, and larger-graph indexing. Shortest path does not validate real-world truth.

05 | Why this is not full GraphRAG

The experiment does not read raw documents and ask an LLM to discover entities or relations. It does not automatically build a knowledge graph, generate natural-language graph queries, provide graph-guided answer generation, or test production-scale indexing. Instead, it establishes one clear reusable component: deterministic traversal over evidence-linked, directed graph edges.

Data quality limitation: if a manually entered relation is incorrect or stale, a correct BFS implementation will still follow it. Independent path checking validates correspondence to the fixture, not the real-world truth of every source statement.
