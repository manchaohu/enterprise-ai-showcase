RAG | Retrieved context, evidence gate, and generation

A real MiniLM retrieval plus FLAN-T5 generation experiment, with source tracking and a deliberate application-layer refusal case.

← Back to tutorial catalog

01 | Technical requirement: sourced answers

An enterprise might store monitoring instructions, ticket manuals and system explanations in many different files. A user asks where the OpenTelemetry Collector exports trace data. A general-purpose language model might provide a plausible response, but that alone does not show which local reference supported it.

Retrieval-Augmented Generation (RAG) explicitly divides the work: retrieve a relevant source, supply it to a generator, then make it possible to inspect which evidence was selected. This is not a guarantee of answer truthfulness; it is an observable engineering workflow.

02 | Architecture: retrieval and generation

The experiment uses genuine pretrained sentence-transformers/paraphrase-MiniLM-L3-v2 to encode four short technical documents and questions as 384-dimensional neural vectors. Cosine similarity ranks documents; the application records the top three results and selects the top one as context for the next step.

A second genuine pretrained network, google/flan-t5-small, receives the selected context and question, and generates a short English answer on CPU. The application then attaches the actually retrieved document ID. That ID is added by the application, not invented or checked by the language model.

03 | Execution pipeline and fixture inputs

1. Embed
Four synthetic English snippets
2. Retrieve
Cosine similarity, top-3 ranking
3. Gate
Simple lexical evidence check on top-1
4. Generate
FLAN-T5 if approved; attach source ID

The application uses a conservative lexical rule: at least two non-stopword terms must appear in both the question and the top document. If that gate fails, the system returns an insufficient-evidence response before running the generation model. This is an application policy, not proof that the model knows when it lacks knowledge.

Saved machine evidence contains the original question, ranked document IDs and cosine scores, the chosen source text, prompt, raw model output, final answer and separate checks. The examples are synthetic English technical snippets, not real private enterprise documents.

04 | Measured output and gate decisions

Executed source excerpts; full code is in the private repository: projects/13-real-rag/rag_e2e.py

Normalized vectors and retrieval rank

SentenceTransformer encodes four synthetic passages and the query as normalized vectors. A matrix product computes cosine similarities; document ID breaks equal-score ties. There is no deployed vector database.

    embedder = SentenceTransformer(EMBED_MODEL, device="cpu")
    doc_vectors = embedder.encode(
        [doc["text"] for doc in DOCS], normalize_embeddings=True,
        convert_to_numpy=True, show_progress_bar=False
    )
    if doc_vectors.shape != (len(DOCS), 384) or not np.isfinite(doc_vectors).all():
        raise RuntimeError("Real embedding dimensions or values invalid")

    tokenizer = AutoTokenizer.from_pretrained(GEN_MODEL)
    generator = AutoModelForSeq2SeqLM.from_pretrained(GEN_MODEL).to("cpu").eval()

    cases = []
    for case in CASES:
        query_vector = embedder.encode(
            [case["question"]], normalize_embeddings=True,
            convert_to_numpy=True, show_progress_bar=False
        )[0]
        scores = doc_vectors @ query_vector
        ranked = sorted(
            zip(DOCS, scores), key=lambda item: (-float(item[1]), item[0]["id"])
        )
        best = ranked[0][0]
        allowed, overlap = evidence_gate(case["question"], best)

Application refusal and model generation

A lightweight lexical evidence gate checks non-stopword overlap with the top document. Rejection is generated by application code without an LLM call. Accepted queries create a contextual prompt for FLAN-T5, and the application appends the retrieved source ID.

        if not allowed:
            # This refusal is an APPLICATION guard, not an LLM-generated answer.
            entry["answer"] = "Insufficient evidence in the local knowledge base."
            entry["checks"] = {"unsupported_refused": case["expected_doc"] is None}
        else:
            prompt = (
                "Answer the question using ONLY the context. Give the shortest exact "
                "factual answer. If context does not answer, say unknown.\n"
                "Context: " + best["text"] + "\n"
                "Question: " + case["question"] + "\nAnswer:"
            )
            tokenized = tokenizer(prompt, return_tensors="pt", truncation=True, max_length=384)
            with torch.inference_mode():
                output_ids = generator.generate(
                    **tokenized, max_new_tokens=36, do_sample=False, num_beams=2
                )
            output = tokenizer.decode(output_ids[0], skip_special_tokens=True).strip()
            entry["prompt"] = prompt

Integration boundaries

Production integration requires document ACLs, recall evaluation, citation faithfulness checks, and better unsupported-answer controls. Lexical overlap cannot prove grounding.

06 | Source code and evidence

Attaching [DOC-OTEL] to a response says which document the retrieval code selected, but it does not establish that every generated sentence is supported by that document. Simple word overlap is not semantic entailment; it can reject valid paraphrases or accept misleading overlaps. The tiny sample does not measure Chinese-language performance, retrieval recall, hallucination rates, data security or production scalability.

Reproducibility: both pretrained model downloads were requested at moving main revisions; immutable checkpoint pins were still an open limitation. Real model execution must not be confused with a version-stable benchmark.
