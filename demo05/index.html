异步队列：任务失败、重复提交后怎样恢复？

将长任务交给后台执行之后，系统必须决定如何应对重复提交、暂时失败、工作者崩溃和最终失败。没有可靠的状态管理，任务可能丢失、重复执行或一直卡住。

01｜这项技术要解决什么问题

将长任务交给后台执行之后，系统必须决定如何应对重复提交、暂时失败、工作者崩溃和最终失败。没有可靠的状态管理，任务可能丢失、重复执行或一直卡住。

02｜核心技术与实现机制

项目基于 Python 标准库 SQLite 实现事务型队列，包括幂等请求键、租约领取、重试延期、租约过期回收、最大尝试次数、死信和成功完成。验证脚本利用模拟逻辑时钟推动状态，而没有真正启动长期运行的后台工作进程。

03｜实际实验输入与执行过程

同一请求键重复提交必须返回同一任务 ID；不同内容同键必须冲突。脚本让任务失败后延时、模拟 worker 崩溃、恢复领取并最终进入 dead 状态；另一任务成功进入 done。每步读取数据库状态。

04｜真实验收与观察到的结果

实际 SQLite 状态迁移与断言通过，证据包含 ASYNC_SQLITE_QUEUE_E2E_PASS、dead/done 状态、重试次数、幂等拒绝与 simulated_logical_clock 字段。
