TinyTimeMixer｜512 小时历史预测 96 小时未来

真实 Granite TinyTimeMixer 预测实验：从历史观测、时间边界、真实基线到可核验的误差，而不仅是一条好看的曲线。

01｜技术需求：96 小时预测及验收指标

企业监控系统会持续产生温度、流量、吞吐和负载数据。管理者关心的不只是“现在是多少”，还希望提前知道未来的变化，安排设备检修或容量。传统办法可以简单地假设未来与最后一个数值相同；如果数据存在每天重复的规律，也可以直接复用前一天的 24 小时变化。

只有把 AI 模型与这些朴素方法比较，才能看清复杂模型是否真正带来增量。 本篇通过真实的变压器油温序列，观察预训练模型在两个时间窗口下的表现。这是受限工程演示，而非电力安全预测系统。

02｜技术方案：历史输入与未来输出

本实验使用 IBM Granite TinyTimeMixer R2 的预训练 512→96 版本，输入是 512 个连续的小时油温读数，模型一次产生接下来 96 小时的预测值。这里使用的是公开数据集 ETTh1 中的油温字段 OT，而不是人为绘制的正弦曲线；模型按固定版本加载并在 CPU 上执行，实验没有现场训练或微调。

关键的一步是避免未来信息泄漏：均值和标准差只允许从 512 个历史点计算，不能提前用未来 96 个观测值调整模型输入。预测完成以后，才能用未来实际值计算误差。这保证了本次脚本的时间顺序正确，但并不证明相关数据从未出现在模型上游预训练语料中。

每窗口过去 512 小时
③ 预测未来

④ 误差复算
比较实测与两种基线

实际工程还产生两种无需神经网络的对照：一是“最后一个值持续 96 小时”，二是“把过去 24 小时的数值重复四次”。前者检验变化趋势是否值得建模，后者检验日周期能否解释未来。程序保存了全部预测、实际值及基线值，并分别计算 MAE（平均绝对误差）和 RMSE（均方根误差）。

在这组样本中，共运行两个 96 小时窗口，累计得到 192 个真实模型预测值。独立脚本会核对每个预测对应的时间戳、输入与标准化边界，以及两条基线和误差指标。

历史窗口与标准化

`split_at` 从预测时点之前提取 512 个小时作为输入，后续 96 小时留给评估。标准化统计量只由历史值计算，避免把未来答案泄漏到模型输入；长度错误和方差退化会抛异常。

def split_at(rows,end_index:int):
    if end_index<CONTEXT or end_index+HORIZON>len(rows):
        raise ValueError("Need 512 historical points plus 96 forward ground-truth points")
    past=rows[end_index-CONTEXT:end_index]
    future=rows[end_index:end_index+HORIZON]
    if len(past)!=CONTEXT or len(future)!=HORIZON:
        raise ValueError("Window length mismatch")
    # Fit only on the 512 historical observations; no future leakage.
    values=[v for _,v in past]
    mean=statistics.mean(values)
    std=statistics.pstdev(values)
    if not 0.000001<std<1000000:
        raise ValueError("Degenerate history-only standard scaler")
    return past,future,mean,std

张量契约与基线评估

标准化后的输入形状是 `[1,512,1]`，TinyTimeMixer 输出应为 `[1,96,1]`。结果用历史均值、标准差反变换，与持久性和 24 小时季节基线在相同未来窗口上比较 MAE/RMSE。

    for number,end in enumerate((len(rows)-2*HORIZON,len(rows)-HORIZON),start=1):
        past,future,mean,std=split_at(rows,end)
        normalized=[(value-mean)/std for _,value in past]
        tensor=torch.tensor(normalized,dtype=torch.float32).view(1,CONTEXT,1)
        run_start=time.monotonic()
        with torch.inference_mode():
            output=model(past_values=tensor,return_loss=False)
        pred=output.prediction_outputs
        if list(pred.shape)!=[1,HORIZON,1]:
            raise RuntimeError(f"Unexpected trained model forecast shape {list(pred.shape)}")
        floats=[float(x)*std+mean for x in pred[0,:,0].detach().cpu().tolist()]
        if not all(math.isfinite(v) for v in floats):
            raise RuntimeError("Model forecast contains nonfinite values")
        actual=[value for _,value in future]
        persistence,seasonal=naive_forecasts([v for _,v in past])

06｜复现步骤和证据核验

这次实验验证了预训练模型在公开历史序列上的 CPU 推理、数据隔离步骤以及与简单基线的数值比较。它没有证明业务现场会持续达到类似误差，也没有验证缺失采样、设备故障、数据漂移或极端值下的行为。尤其应注意：局部未来的 96 小时虽然没有进入脚本输入，但上游预训练数据的完全隔离尚未得到保证。

使用边界：没有概率预测区间、企业现场报警策略、长期回测或生产 SLO；真实数据集和预训练权重的再分发条件应分别确认。两次受限演示的 MAE 不应外推成普适精度保证。
