Agent 审批：什么情况下允许 AI 修改工单？

如果 Agent 能关闭工单或写入数据库，就必须在真正执行前验证是否获得授权，而且批准必须与操作类型、目标工单和参数绑定，不能批准一次之后随意替换对象。

01｜这项技术要解决什么问题

如果 Agent 能关闭工单或写入数据库，就必须在真正执行前验证是否获得授权，而且批准必须与操作类型、目标工单和参数绑定，不能批准一次之后随意替换对象。

02｜核心技术与实现机制

该实验复用真正的 SQLite TicketStore 和应用内 ApprovalGate，检查无审批拒绝、请求者不能自批、未批准不能执行、变更参数使审批无效以及审批只能使用一次。执行后保存允许、拒绝与审计事件。

03｜实际实验输入与执行过程

构造一条待关闭工单，先验证多种未经批准的操作不会改变状态。测试程序中的 reviewer 角色批准正确的 close_ticket 参数后，agent 方可写入 closed；重复消费同一许可则被拒绝。

04｜真实验收与观察到的结果

真实工单关闭、审批前零变更、一次性许可和审计序列得到验证；独立结果 JSON 记录 APPROVED、EXECUTED 与 DENIED 事件。

06｜能力边界与下一步深入方向

审批人只是程序模拟的角色，没有真实用户认证、签名、外部 MCP 传输或并发安全验证；这不是可以直接上线的安全审批产品。
