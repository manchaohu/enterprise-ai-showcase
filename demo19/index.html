Demo 19｜Cross-Encoder 相关性重排：Query–Passage 联合打分

公开在线审读候选（仍待该篇人工内容验收） · 源代码位于私有工程仓库 · 实验结论只适用于声明的验证范围

原始源码（需访问权限）：19-real-reranker　 Actions Run：39374021955

1. 技术需求与验收

给定初步召回的五条文本候选，使用真实 MS MARCO Cross-Encoder 为每个 Query–Passage 配对计算相关性分数并重新排序。两条人工构造问题分别问 Jaeger Trace 可视化位置和扫描 PDF 的 OCR 工具；每条问题的预期 Top1 不同。目标是证明模型确实参与候选顺序调整，不评估生产检索质量。

2. 技术方案和数据链路

模型 cross-encoder/ms-marco-MiniLM-L6-v2 使用固定提交的 tokenizer 与 BertForSequenceClassification 单 logit head。对每个问题复制五份 query，与五段候选成对 Tokenize；模型返回 [5,1] logits，再按数值从高到低排序，遇到相同分数用原始候选序号稳定排序。这里的得分是原始 logit，不是经过概率校准的相关性概率。

3. 核心实现及关键代码

3.1 成对输入与单 logit head

对应源码：reranker_e2e.py — 关键代码节选（省略上下文，不可直接独立执行）

batch = tokenizer([case["query"]]*len(DOCUMENTS),
  [doc["text"] for doc in DOCUMENTS],
  padding=True,truncation=True,max_length=256,return_tensors="pt")
with torch.inference_mode():
    logits = model(**batch).logits
if list(logits.shape) != [len(DOCUMENTS),1]:
    raise RuntimeError("Unexpected trained ranking head")

Cross-Encoder 将 query 与文档放在同一次模型输入中，允许交叉注意力比较具体词项关系，因此每次有 N 个候选就需要 N 次配对计算（可批处理）。truncation=True,max_length=256 会截断长文档；需要先切分或挑选相关片段。与独立生成句向量并缓存近邻的 Bi-Encoder 不同。

3.2 按模型原始分数排序

对应源码：reranker_e2e.py — 关键代码节选（省略上下文，不可直接独立执行）

scores=[float(x) for x in logits.detach().cpu().view(-1).tolist()]
order = sorted(range(len(DOCUMENTS)),
               key=lambda i:(-float(scores[i]),i))
ranked=[{"rank":rank, "id":DOCUMENTS[i]["id"],
         "model_raw_logit":round(scores[i],7)}
         for rank,i in enumerate(order,start=1)]

排序时只使用模型输出，不把 expected_top_id、关键词或测试标签写入得分。使用候选下标作为并列优先级可保证重复性。分数可以有负值，不应跨查询当作绝对概率比较。测试在排序完成后才核对预期 Top1。

5. 工程使用与集成

适合放在 BM25/向量召回之后，对 Top20–100 等少量候选做精排。工程实现需控制每个候选的 Token 长度、批大小、GPU/CPU 延迟与超时，以及评价 nDCG、Recall@k 和人工相关性标签。首阶段召回缺失的文档不会被 Cross-Encoder 重新找回。
