1. 技术需求与验收条件

通过 MCP SDK 建立独立工具服务。Client 需要发现 create_ticket、get_ticket、close_ticket，通过标准协议调用服务，并把执行结果写入 SQLite。测试使用同一个 request_key=case-001 重复创建，验收要求数据库只有一条记录，工单能查询和关闭。

2. 技术方案与执行链

运行进程分为 MCP Client 与以 stdio 启动的 FastMCP Server。Server 将工具调用映射到 TicketStore；SQLite 保证事务化保存。测试通过 ClientSession.initialize() 建立会话，再执行 list_tools() 与 call_tool()。该 Demo 直接验证 MCP 协议，不需要 LLM；Demo 14 才由真实模型生成工具调用提议，两者的职责不同。

3. 核心实现与代码要点

3.1 声明 MCP 工具

源码位置：server.py · 关键片段（其余逻辑见完整源码）

mcp = FastMCP("enterprise-ticket")
@mcp.tool()
def create_ticket(request_key: str, title: str) -> dict:
    return store.create(request_key, title)
if __name__ == "__main__":
    mcp.run(transport="stdio")

@mcp.tool() 把 Python 函数暴露成可发现工具。类型注解及函数文档用于向 Client 描述参数与用途，实际工单数据由 TicketStore 完成存取。stdio 以标准输入/输出承载协议，服务进程不能把调试文字直接打印到 stdout，否则可能破坏协议消息。该实现没有远程鉴权或 HTTP 网关。

3.2 客户端初始化与结果兼容处理

源码位置：verify_mcp.py · 关键片段（其余逻辑见完整源码）

params = StdioServerParameters(
    command=sys.executable, args=[str(ROOT / "server.py")], env=env)
async with stdio_client(params) as (reader, writer):
    async with ClientSession(reader, writer) as session:
        await session.initialize()
        tools = await session.list_tools()
        first = payload(await session.call_tool("create_ticket", {
            "request_key":"case-001", "title":"Cannot log in"}))

StdioServerParameters 指定启动可执行程序、脚本路径和 TICKET_DB 环境变量，测试为每次运行分配独立临时数据库。payload() 优先读取 structuredContent，必要时解析文本块中的 JSON，同时检查 isError，以适配 SDK 的响应包装差异。Client 不直接调用 store.create()，因此协议消息往返本身进入验收范围。

3.3 数据库唯一键与幂等重试

源码位置：ticket_store.py · 关键片段（其余逻辑见完整源码）

db.execute("INSERT OR IGNORE INTO tickets(request_key,title) VALUES (?,?)",
           (request_key, title))
row = db.execute("SELECT * FROM tickets WHERE request_key = ?",
                 (request_key,)).fetchone()
if row["title"] != title:
    raise ValueError("idempotency key reused with different title")

数据库对 request_key 设置 UNIQUE。同一键同一标题的重试会返回已有记录；同一键对应不同标题会失败，避免错误地吞掉不同业务请求。? 参数绑定避免通过 SQL 字符串拼接注入值。这个机制保证单键业务幂等，不等于分布式跨系统事务。
