MCP 工单工具：AI 如何调用真正的企业操作？

当 AI 助手需要创建、查看或关闭工单时，不能把回答一段文字当成实际业务操作。本实验关注模型上下游的工具通信机制：客户端怎样发现服务端提供的能力，怎样传递参数，并确保 SQLite 中的工单状态真实改变。

01｜这项技术要解决什么问题

当 AI 助手需要创建、查看或关闭工单时，不能把回答一段文字当成实际业务操作。本实验关注模型上下游的工具通信机制：客户端怎样发现服务端提供的能力，怎样传递参数，并确保 SQLite 中的工单状态真实改变。

02｜核心技术与实现机制

使用官方 Python MCP SDK 建立 stdio 客户端与服务端会话。客户端完成 initialize 后执行 list_tools，发现 create_ticket、get_ticket 和 close_ticket，再通过 call_tool 发送 JSON 参数。工单写入独立 SQLite 存储，通过请求键保持创建幂等。

03｜实际实验输入与执行过程

脚本创建临时数据库，提出一次 Cannot log in 工单创建请求，然后以同一请求键重试、读取工单状态、关闭工单，再重复关闭并直接读取 SQLite。验收要求最终只有一条持久化工单、状态为 closed。该脚本测试真实 MCP 协议而不需要模型自动规划工具。

04｜真实验收与观察到的结果

实际专项 Actions 已完成官方 SDK 工具发现、调用和工单持久化验收，结果标识 OFFICIAL_MCP_STDIO_PASS。与早期迁移档案中的“SDK 尚未验证”不同，本次结果对应后来重新实现并在云端执行的正式工单样例。
