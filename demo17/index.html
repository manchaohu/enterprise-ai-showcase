Demo 17｜扩散模型文生图：真实推理、生成参数与结果检查

工程实践教程 v0.1（中文人工审读通过稿）｜2026-10-23。依据已归档 GitHub Actions 原始 diffusion_evidence.json、sample_01.png、sample_02.png；图片由本工程用 Segmind Tiny-SD 直接生成，公开展示仅用于记录限定范围实验效果；使用模型需遵守 CreativeML Open RAIL-M 许可。Demo 14 v0.4 已作为表达与代码讲解的人工审定基线。

1. 技术需求与验收条件

输入两条英文文字提示词，调用真实预训练扩散模型生成两张 256×256 RGB PNG，并保存影响复现的模型版本、生成随机种子、推理配置及文件哈希。验收要求经过预训练权重加载和实际去噪步骤，输出可读取的 PNG，并能由独立验证程序重新核对；不把空白图片或程序预绘制的图当成扩散推理结果。

本实验采用 Segmind Tiny-SD、Diffusers StableDiffusionPipeline、PyTorch float32 CPU。两个不同提示词的实验参数均为 6 个去噪步骤、guidance_scale=1.0，每个样例分别固定一个随机种子。6 steps 是用于跑通真实模型链路的低成本设置，不是画质最佳配置。

2. 技术方案与执行链

自然语言提示词 + 固定随机种子
             ↓
Tiny-SD 预训练权重 + tokenizer/text encoder
             ↓
初始潜变量噪声 → UNet 多轮噪声预测 → 调度器更新潜变量（6次）
             ↓
VAE 解码图像 → Pillow PNG 保存
             ↓
哈希 / 尺寸 / 颜色统计 → diffusion_evidence.json
             ↓
verify_evidence.py 独立核验图片及实际去噪记录

Diffusers Pipeline 封装了文本条件、潜变量去噪、调度器和 VAE 解码。在本案例中 DPMSolverMultistepScheduler 是实际记录到的调度器，核心推理在 CPU 上执行。callback_on_step_end 收集每次完成的步骤索引，作为“真实执行 6 次去噪”的可核查运行记录。

3. 核心实现与代码要点

3.1 固定模型版本与输入

源文件：diffusion_e2e.py（私有，代码节选）。

MODEL_ID = "segmind/tiny-sd"
MODEL_REVISION = "3d25de3e8d5aacf94ce91176f204e6d11d120315"
STEPS = 6
SIZE = 256
EXAMPLES = [
    {"case_id": "sample_01", "seed": 172001,
     "prompt": "A single red apple on a wooden table, product photograph, soft daylight."},
    {"case_id": "sample_02", "seed": 172002,
     "prompt": "A blue ceramic mug on a kitchen table, product photograph, soft daylight."},
]

MODEL_REVISION 固定不可变提交，避免后续模型仓库 main 更新影响比较。随机种子用于初始化每次的噪声生成器，在给定代码、模型及环境下提高复现性；它不等于跨硬件完全逐像素一致的保证。两条 prompt 和 seed 同时发生变化，因此本实验不能单独证明提示词差异造成了输出差异。

3.2 加载真实权重与低内存推理

pipe = StableDiffusionPipeline.from_pretrained(
    MODEL_ID, revision=MODEL_REVISION, torch_dtype=torch.float32,
    use_safetensors=True
).to("cpu")
pipe.enable_attention_slicing()
params = list(pipe.unet.parameters())
sampled = params[0].detach().flatten()[:2048]
nonzero = int(torch.count_nonzero(sampled).item())
if nonzero < 16:
    raise RuntimeError("UNet weights appear empty/uninitialized")

from_pretrained() 从指定版本读取预训练组件，to("cpu") 将模型放在 CPU 上；float32 兼顾本实验环境的 CPU 兼容性。enable_attention_slicing() 缩减注意力处理过程的峰值内存需求，但可能影响运行速度。nonzero 检查排除明显空权重的异常情况；仅检查非零值本身不足以证明参数经过训练，因此更完整的证据还依赖指定模型版本、调用链和真实产物。

3.3 去噪、回调记录与 PNG 保存

gen = torch.Generator(device="cpu").manual_seed(item["seed"])
step_log = []
def on_step_end(pipeline, step, timestep, callback_kwargs):
    step_log.append(int(step))
    return callback_kwargs
with torch.inference_mode():
    out = pipe(
        prompt=item["prompt"], generator=gen,
        num_inference_steps=STEPS, guidance_scale=1.0,
        width=SIZE, height=SIZE, output_type="pil",
        callback_on_step_end=on_step_end
    )
if step_log != list(range(STEPS)):
    raise RuntimeError("Actual denoising steps differ from contract")

num_inference_steps 决定本次运行调度器的迭代次数；guidance_scale=1.0 使该配置不使用高于 1 的文本无分类器引导强度，计算量适合低预算示例。callback_on_step_end 记录每步结束时的序号，最后要求 [0,1,2,3,4,5]，防止在未执行完整链路时误判成功。后续将 out.images[0] 保存为 PNG；图片尺寸、RGB 方差、熵值、不同颜色数量及 SHA-256 都写入证据 JSON。

3.4 结果验证器与失败处理

verify_evidence.py 对模型 ID、提交、设备、去噪次数、提示词与种子逐项核对；再次打开 PNG 计算哈希和图像熵，并确认两张 PNG 不同。任何断言不满足时核验失败。

diffusion_e2e.py 捕获执行异常后将状态写为 PRETRAINED_DIFFUSION_BLOCKED，不会把图片缺失、模型权重下载失败或不完整迭代伪装为 PASS。这些检查关注运行真实性和产物完整性，并不评估文字和图片的语义匹配度。

6. 技术边界与取舍

  • 256×256、6 步、两个英文 prompt 属于低成本真实推理，不代表实际生成质量、系统吞吐、GPU 延迟或商业部署效果。
  • 模型许可为 OpenRAIL-M；本教程内部阅览与公开对外分发要分开审查，模型权重不随教程分发。
  • 图像 SHA-256、熵、非空检查可确认文件与运行记录关联，不能证明人眼质量、提示词理解或物体结构正确。
  • 两个样例的 prompt 与 seed 都不同，不能据此做严格因果对照。后续如需测试 prompt 对结果的影响，应保持相同 seed 及模型配置，只改变 prompt。
  • 若目标是高质量生产图片，应另外评估模型分辨率、去噪步数、图像一致性、版权和推理成本，不直接将本 Demo 配置用于生产。
