1. 技术需求与验收条件

追踪一个 HTTP 请求在 Gateway 与 Backend 两个进程中的执行路径，识别客户端请求、后端处理和存储查询之间的父子关系。验证包括正常、慢请求和错误请求，要求 Collector 收到真实 OTLP Span，并由 Jaeger 按 Trace ID 检索。

2. 技术方案与执行链

Docker Compose 创建 Gateway、Backend、OTel Collector 和 Jaeger 四个服务。Gateway 对外接受请求并调用 Backend；各服务使用 SDK 创建 Span，经 OTLPSpanExporter 输出到 Collector 的 /v1/traces；Collector 再送入 Jaeger。span 的 trace_id 连接整个请求，span_id 和 parent_span_id 定义父子关系，服务名称来自 Resource。

3. 核心实现与代码要点

3.1 初始化追踪导出器

源码位置：src/otel_demo/otlp_service.py · 关键片段（其余逻辑见完整源码）

provider = TracerProvider(resource=Resource.create({
    "service.name": name, "service.version": "2.0-demo"}))
exporter = OTLPSpanExporter(endpoint=endpoint, timeout=5)
provider.add_span_processor(BatchSpanProcessor(exporter,
    schedule_delay_millis=500))
tracer = provider.get_tracer("otel_demo.otlp_service")

service.name 区分 Gateway 与 Backend。BatchSpanProcessor 异步批量导出以降低业务线程直接发请求的开销，schedule_delay_millis=500 是批次调度间隔，不是端到端 SLA。进程清理阶段调用 force_flush() 和 shutdown()，否则快速退出时最后一批 Span 可能丢失。

3.2 Collector 接收与导出

源码位置：collector-config.yaml · 关键片段（其余逻辑见完整源码）

receivers:
  otlp:
    protocols:
      http:
        endpoint: 0.0.0.0:4318
processors:
  batch:
    timeout: 1s
exporters:
  otlp_http/jaeger:
    endpoint: http://jaeger:4318

两个应用进程指向 http://collector:4318/v1/traces；Collector 使用 OTLP HTTP Receiver 接收，批量处理后发往 Jaeger 容器。这里的 http://jaeger:4318 是 Collector 的 exporter 基础端点，不是浏览器查看端口；Jaeger UI 单独监听 16686。这份配置是工程提交的示例配置，其有效性以端到端运行检查为准。

3.3 查询 Jaeger 并验收 Span

源码位置：scripts/verify_collector_jaeger.py · 关键片段（其余逻辑见完整源码）

REQUIRED = {"gateway.http.request", "gateway.http.client.backend",
            "backend.http.request", "backend.storage.query"}
MODES = ("ok", "ok", "ok", "slow", "slow", "error")
# Verifier polls Jaeger /api/traces/{trace_id} and checks required spans.

测试会发起六次请求，并核对状态码：前五次为 200，错误模式为 502。每个 Trace 必须包含四个关键操作、Gateway 和 Backend 两个 service；等待超时仍未在 Jaeger 检索成功则 FAIL。/api/traces/{id} 是 Jaeger UI 的内部接口，不应在生产集成中将它当作稳定外部 API。

5. 使用与工程集成

复现命令（需私有仓库访问权限）

cd projects/03-opentelemetry
python -m pip install -r requirements.txt
python scripts/run_compose_e2e.py

在现有服务中为 HTTP Server、HTTP Client、数据库查询分别建立 Span，保证下游请求传播上下文。为追踪数据设定采样、敏感属性过滤、保留周期和采集开销预算；应用层告警应结合 metrics/logs，而非只依赖 Trace。Windows 公司设备不能运行 Docker Desktop 时，可在支持 Docker 的 GitHub Actions 环境执行，本项目已有对应 CI 路径。
