01｜这项技术要解决什么问题

与程序直接预设函数调用不同，真正的 Agent 工具链要让模型根据用户意图选择函数及参数，再由可信应用决定是否执行。模型提出的建议与业务系统真正产生的副作用必须清晰区分。

02｜核心技术与实现机制

使用预训练 Qwen2.5-0.5B-Instruct，将 tools 定义传入 tokenizer chat template，在 CPU 上读取真实生成的 tool_call JSON，执行 JSON Schema 校验和应用层布尔批准，再调用 SQLite TicketStore。

01真实 Qwen 生成提议
02JSON Schema 校验
03审批拒绝或许可
04SQLite 状态回读

流程示意，非真实模型输出曲线。

03｜实际实验输入与执行过程

对三条英文指令分别验证 create、get、close 的模型提议和参数；写操作先未批准调用，要求被阻断，再允许相同提议并回读数据库。非法结构和非允许工具反例属于程序构造，未被冒称模型输出。

04｜真实验收与观察到的结果

真实模型输出、审批前后效果与 SQLite 读回都获得专项 CI 成功证据。原始 tool_call_evidence.json 记录模型建议和核验结果，未用固定函数名替换生成内容。
