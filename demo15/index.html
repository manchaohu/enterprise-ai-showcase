1. 技术需求与验收条件

为模型提供两张颜色不同的合成图片，在完全相同的英文问题下得到对应颜色答案。输入必须包含实际像素张量，且模型需真实执行推理。测试的目标是验证图像条件是否参与问答链路，而非评估现实图片的通用理解能力。

2. 技术方案与执行链

Pillow 创建 512×512 白色底图和一个大色块。AutoProcessor 将图片和对话模板编码成模型输入；AutoModelForVision2Seq 采用 SmolVLM-256M-Instruct CPU float32 前向生成，再从输出 Token 中裁剪提示部分并解码答案。测试分别核对 red 和 blue，记录图片 SHA-256、输入像素张量形状及真实回答。

3. 核心实现与代码要点

3.1 构造图像与图像证据

源码位置：vlm_e2e.py · 关键片段（其余逻辑见完整源码）

image = Image.new("RGB", (512, 512), "white")
ImageDraw.Draw(image).rectangle((40, 40, 471, 471), fill=rgb)
image.save(destination, format="PNG")

图片是有明确真实 RGB 参数的程序生成测试数据。固定底色、形状和问题，只更改目标颜色，可把模型输出与输入变量建立清晰对应关系。它排除了真实照片中的背景复杂性，但也使任务显著简单，不宜当作通用视觉能力评估。

3.2 生成多模态张量

源码位置：vlm_e2e.py · 关键片段（其余逻辑见完整源码）

processor = AutoProcessor.from_pretrained(MODEL_ID,
    size={"longest_edge": 512})
messages = [{"role":"user", "content":[
    {"type":"image"}, {"type":"text", "text":QUESTION}]}]
prompt = processor.apply_chat_template(messages, add_generation_prompt=True)
inputs = processor(text=prompt, images=[im.convert("RGB")],
                   return_tensors="pt")
assert inputs["pixel_values"].numel() > 0

<image> 位置由模板管理，像素经过 Processor 的视觉预处理变成 pixel_values。存在非空像素张量是本例的必要验收条件，避免无图输入仍生成颜色词。模板和图像占位符的细节依模型而异，迁移到其他 VLM 时要优先替换模型对应的 Processor 与聊天模板。

3.3 解码答案与后验检查

源码位置：vlm_e2e.py · 关键片段（其余逻辑见完整源码）

generated_ids = model.generate(**inputs, max_new_tokens=36,
    do_sample=False, pad_token_id=processor.tokenizer.eos_token_id)
new_ids = generated_ids[0][inputs["input_ids"].shape[-1]:]
answer = processor.decode(new_ids, skip_special_tokens=True).strip()

裁剪已有 input_ids 的长度，只保留模型新增的输出 token；若直接解码完整序列，可能把问题文本误计为回答。do_sample=False 适合确定性样例。check_answer() 用正则只检测 red/blue 词，并要求输出的颜色集合恰好与期望一致；更复杂问答不能仅用关键词作通用质量指标。
