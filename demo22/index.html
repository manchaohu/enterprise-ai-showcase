1. 技术需求与验收

用 hnswlib 对 2048 条 48 维合成向量建立余弦近邻索引，执行 36 条查询、每条取 Top10，并使用暴力精确搜索作为参考计算 Recall@10。随后将索引写入磁盘再加载，比较查询 ID 和距离是否保持一致。测试真实 HNSW 索引库，但不涉及预训练向量编码器。

2. 技术方案和数据链路

随机种子 20261020 固定构造语料与受扰动查询，并规范化到单位长度。HNSW 初始化 M=16、ef_construction=120，查询阶段使用 ef_search=100；数据以单线程顺序加入，记录构建、查询与精确扫描耗时。保存二进制索引再重载后必须重新设置 ef_search，因为 hnswlib 文件格式不会保留该运行时参数。

3. 核心实现及关键代码

3.1 建立余弦 HNSW 索引

对应源码：hnsw_e2e.py — 关键代码节选（省略上下文，不可直接独立执行）

index = hnswlib.Index(space="cosine", dim=DIM)
index.init_index(max_elements=COUNT,
  ef_construction=EF_CONSTRUCTION,M=M,random_seed=17)
index.add_items(corpus, ids, num_threads=1)
index.set_ef(EF)
ann_ids, ann_distances = index.knn_query(queries,k=K,num_threads=1)

M 控制连接数近似上限，ef_construction 影响构建质量和成本，ef_search 控制查询期候选搜索规模与召回/延迟权衡。space=cosine 返回余弦距离，不能当余弦相似度直接排序。单线程配置提高可重复性，并不用于证明峰值吞吐。

3.2 精确对照、Recall 与重载

对应源码：hnsw_e2e.py — 关键代码节选（省略上下文，不可直接独立执行）

exact = np.argsort(-(queries @ corpus.T),axis=1,kind="stable")[:,:K]
index.save_index(str(index_path))
reloaded.load_index(str(index_path),max_elements=COUNT)
reloaded.set_ef(EF)
after_ids, after_distances = reloaded.knn_query(queries,k=K,num_threads=1)
assert np.array_equal(ann_ids,after_ids)

暴力计算全部余弦得分，再取精确 TopK 作为对照，逐 query 计算交集/10。二进制持久化和数据向量都记录 SHA-256，保证报告与原始文件一致。重载验证关注相同查询是否返回相同邻居，不等同于跨版本、跨机器或动态增删索引的兼容性测试。

5. 工程使用与集成

可放在语义检索、图像相似搜索或推荐候选召回中，但业务向量生成、版本管理、过滤权限、索引增删、持久化恢复与冷热切换需要另行集成。上线之前应对不同 M/ef 和数据分布建立召回—延迟曲线，避免把当前 Recall 1.0 当永久保证。
